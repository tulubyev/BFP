# NDVI, NBR и временные ряды для инцидентов

Дата: 2026-09-27. Связано: future.md §7 «Детальная проверка» (NDVI, временной ряд), §14 «Третий
релиз» п. 3. Строится на модуле снимков `backend/services/imagery/` (PR #13, дизайн
`2026-09-27-before-after-imagery-design.md`) — те же сцены, сетки, чтение COG и лимиты.

## Проверено 2026-09-27

- Sentinel-2 C1 через Earth Search с VPS: выбор сцен 3,5–4,5 с, рендер 3,4–4,8 с на картинку.
- MODIS MOD13Q1 через ORNL Web Service с VPS работает, но 24 с на каждые 10 дат (лимит сервиса) —
  ряд 2000–2026 (610 дат) ≈ 25 мин на точку. **Не используем**; ряд строим по Sentinel-2.

## Часть 1. Индексы по снимкам «до/после» (дёшево — те же полосы, что у рендера SWIR)

- Полосы 20 м: B04 (`red`), B8A (`nir08`), B12 (`swir22`), маска `scl`; отражение по `raster:bands`.
- NDVI = (B8A − B04) / (B8A + B04); NBR = (B8A − B12) / (B8A + B12). B8A вместо B08 — одна
  сетка 20 м для обоих индексов (записать в коде и методологии).
- Среднее по пикселям внутри bbox инцидента (контур из URL), только «чистые» по SCL (те же классы,
  что в выборе сцен); `validPct` — доля чистых пикселей bbox. Если чистых < 50 % — `value: null`
  с причиной.
- Для инцидента: NDVI до/после, ΔNDVI = после − до; NBR до/после, **dNBR = NBR до − NBR после**
  с классом по USGS (Key & Benson 2006): < 0,10 — не горело/без изменений; 0,10–0,27 — низкая;
  0,27–0,44 — умеренно-низкая; 0,44–0,66 — умеренно-высокая; ≥ 0,66 — высокая степень выгорания.
  Подпись: «оценка по двум снимкам Sentinel-2, не полевое обследование». dNBR только если обе
  стороны `ok` и «после» не `duringActivity` (во время горения NBR искажён дымом и огнём —
  тогда `null` с причиной).
- Ответ `/api/monitoring/forest-changes/:id/imagery` получает поле `indices` (ключ кэша → `v2`):
  `{ before: {ndvi, nbr, validPct} | null, after: … | null, dNdvi, dNbr, severity: {class, label} | null, reasons }`.
- Новый рендер `ndvi` (−0,2…0,9, палитра коричневый → жёлтый → зелёный, легенда в UI) —
  `RENDERS`, белый список маршрута, `RENDER_VERSION` не менять для старых рендеров.

## Часть 2. Временной ряд (летний NDVI по годам)

- Для каждого года с 2017 по текущий: лучшая сцена в окне 1 июля – 31 августа (пик вегетации,
  без снега) по AOI инцидента — порядок кандидатов как в выборе сцен, чистых ≥ 80 %.
- Значения: средний NDVI внутри bbox инцидента и в «фоне» — AOI минус bbox (кольцо вокруг),
  чтобы отличать изменение на участке от общего по территории (засуха, поздняя весна).
  Плюс дата сцены и `validPct`.
- Год без годной сцены — `{ year, status: 'none', reason }`, никаких интерполяций.
- Текущий год, пока окно не закончилось, помечать `partial: true`.
- **Расчёт в фоне:** `GET /api/monitoring/forest-changes/:id/ndvi-series` →
  `{ status: 'ready' | 'pending', years: [...готовые], progress: {done, total}, source, generatedAt }`.
  Первый запрос ставит задачу в очередь в процессе (не в HTTP), ответ сразу `pending`; UI
  опрашивает раз в 5 с до 3 мин. Не более 1 ряда одновременно (свой лимитер), чтение сцен —
  через общий лимит проверок SCL. Готовые годы кэшируются в Redis по ключу
  `imagery:ndvi-year:v1:<aoi>:<year>` на 365 сут (прошлые годы не меняются), текущий год — 7 сут;
  весь ряд — `cached()` 24 ч. Ошибка сети по году не кэшируется, год остаётся недостроенным
  и пересчитывается при следующем запросе.
- Ограничение: только инциденты с bbox (FIRMS); при сотнях запросов — очередь до 8 рядов,
  дальше 503 «слишком много запросов, попробуйте позже».

## Интерфейс (IncidentModal / IncidentImagery)

- Под снимками — строка индексов: NDVI до/после и ΔNDVI, dNBR с цветной меткой класса и
  подписью-оговоркой; третий вариант переключателя «NDVI» (легенда шкалы).
- Блок «Динамика NDVI (июль–август)»: линейный график (recharts, уже в проекте) — участок и фон
  двумя линиями, точки только за годы со сценой, пропуски не соединять; подсказка с датой сцены
  и долей чистых пикселей; скелетон и «рассчитывается… N из M лет» при `pending`.
- Все подписи — текстовые узлы React. На 375 px график в ширину карточки.

## Тесты (jest)

Формулы индексов на синтетических пикселях (включая деление на 0 и nodata), маска SCL для
статистики, среднее по bbox и по кольцу, пороги dNBR (границы классов), правило `duringActivity`,
окна по годам и `partial`, очередь/лимиты/кэш-ключи, ответ `pending` → `ready`, график:
разрывы на годах без сцен. Сети нет; COG — в памяти, как в тестах PR #13.
