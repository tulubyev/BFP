проверка» (ближайшие дороги), §10 «PDF-отчёт по региону». Четыре независимых агента; у каждого

`future.md`) править минимально и точечно, чтобы слияния были лёгкими.

Общие правила для всех: без миграций БД; никаких новых внешних хостов в браузере (CSP);
SQL только плейсхолдерами (тест-страж `tests/security/sqlGuard.test.ts`); исходящие HTTP —
с `timeout` и `maxContentLength` из `backend/utils/responseLimits.ts` (проверяет
`tests/security/responseLimits.test.ts`); UI-текст по-русски, попапы и подписи — текстовыми узлами;
новая логика — с jest-тестами и чистыми функциями. Сеть из облачной песочницы к NASA, Overpass,
Рослесхозу, GFW, Earth Search может быть закрыта: тесты на фикстурах, реальную проверку делает
основная сессия после слияния — об этом честно написать в PR.

## Q. Контроль качества данных: Рослесхоз, Overpass (ООПТ), GFW

Образец — `backend/services/firmsCsv.ts` и его тест (проверка структуры, построчная отбраковка,
отвергнуть файл целиком при смене формата, последний хороший кэш остаётся, причина в журнале).
Файлы: `backend/services/rosleskhozService.ts`, `overpassService.ts`, `globalForestWatch.ts`,
`gfwTiles.ts` (только разбор ответов), новые модули `backend/services/quality/*`, тесты.

- **Рослесхоз** (CSV наборов + meta.csv): проверять заголовок по ожидаемым колонкам каждого набора
  (`DATASETS` в сервисе), число субъектов в наборах по регионам (≈ 85–100 строк, а не 3 и не 3000),
  числовые поля: не отрицательные, единицы правдоподобны (лесистость 0–100 %, площади > 0);
  набор с сменившейся структурой отвергается, кэш `rosleshoz:*:last-good` остаётся, в журнале
  `failed` с причиной. Проверка мягкая там, где данных мало (ReforestationArea — только итог по РФ).
- **Overpass / ООПТ**: ответ должен быть JSON с `elements`; число объектов правдоподобно (сейчас
  130; отвергать < 50 % от последнего хорошего значения и < 20 абсолютно — «ответ обрезан»);
  у каждой геометрии валидные координаты (WGS84), замкнутые кольца, площадь > 0; невалидные
  объекты отбрасываются с подсчётом; уже есть правило «пустой ответ не заменяет хороший» — не
  сломать.
- **GFW**: ответы Data API и потерь — обязательные поля (`year`, `area_ha`), год в 2001..текущий,
  `area_ha` ≥ 0 и конечное; плитки — MIME `image/png` и размер (пустая/HTML-страница вместо
  плитки → 502, не кэшировать); версия DIST-ALERT в формате `vYYYYMMDD`.
- Итог каждой проверки (отброшено N, причина отказа) виден в журнале загрузок и
  `/api/sources/status`; общий тип результата проверки вынести в `backend/services/quality/`.
- Тесты: фикстуры реальной формы (для Рослесхоза взять структуру из существующих тестов), плюс
  негативные — переименованная колонка, HTML вместо CSV, обрезанный JSON, отрицательные числа.

## S. Свежесть источников без фонового опроса

Сейчас `gfw_loss`, `gfw_cover`, `osm_boundaries`, `sentinel2` в `/api/sources/status` — `unknown`.
Файлы: `backend/services/sourceStatus.ts`, `backend/utils/freshness.ts`, `backend/utils/journal.ts`
(только добавить), `backend/services/sourceRegistry.ts` (флаги/пороги), `backend/routes/tiles.ts`,
`backend/services/gfwTiles.ts` (только запись успеха/сбоя), `backend/services/imagery/stac.ts`
(только запись), `frontend/src/map/sourcesControl.ts`, `frontend/src/map/sourcesStatus.ts`,
`frontend/src/methodology/SourcesList.tsx` при необходимости.

- **Журнал по запросам**: для источников, к которым ходят по требованию (плитки GFW: `gfw_loss`,
  `gfw_cover`, `gfw_dist`; каталог Sentinel-2), записывать «последнее успешное / неудачное
  обращение к источнику» — не чаще раза в 10 минут на источник (ограничитель в памяти), в Redis
  через `recordRun`. Это сигнал «мы ещё можем достучаться», а не свежесть данных источника.
- **Пороги**: обращение считать устаревшим, если успешных нет дольше X (для плиток GFW — 3 суток
  без единого успеха при наличии неудач; если обращений просто не было — `unknown`, не `failed`).
- **`osm_boundaries`**: свежесть — из имени файла границ (`ru-regions.<YYYY-MM>.geojson`, версия
  границ) с порогом 18 месяцев; показать версию в статусе.
- Состояние источника = худшее из сигналов (как для Рослесхоза в `DOWNLOAD_THRESHOLDS`).
- Карта (`sourcesControl`) и страница методологии показывают новые состояния без ошибок; подпись
  различает «данные устарели» и «источник недоступен для нас».
- Тесты: пороги, ограничитель записи, худшее из сигналов, `unknown` без обращений.

  параллельных запросов к Overpass — 1 (очередь через `backend/utils/limiter.ts`), чтобы карточки

- Rate limit: в `EXPENSIVE_API_PATHS` (`backend/middleware/apiProtection.ts`) добавить путь

- UI: в блоке «Место» карточки строки «Ближайшая дорога: … в N км», «Ближайший населённый пункт:
  … в N км (на …)»; загрузка/ошибка как у остальных строк блока.
