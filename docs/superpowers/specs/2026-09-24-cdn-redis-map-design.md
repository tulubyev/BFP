# CDN, Redis и улучшения карты — дизайн

Дата: 2026-09-24. Прод: https://forestwatch.ru (VPS 90.156.168.149, Docker + Traefik).

## Контекст

Аудит 2026-09-23 показал: слой ООПТ пуст (Overpass вернул пустой ответ, он закэширован как успех),
GLAD Landsat отдаёт 422 и не покрывает Россию, «Лесной покров» v1.9 и ФГИС ЛК WMS мертвы,
потери леса показаны v1.9 (2001–2021) при легенде «2001–2023». JS 828 КБ и API отдаются без
сжатия, у хешированных ассетов `max-age=0`. Кэши FIRMS/ООПТ/Рослесхоза живут в памяти процесса
и теряются при каждом рестарте. 3258 термоточек рисуются DOM-маркерами.

## Решения

- CDN: Beget CDN на отдельном поддомене `cdn.forestwatch.ru`, origin — `forestwatch.ru`.
  Через CDN — только неизменяемая статика (ассеты Vite, версионированные файлы границ) и
  проксированные плитки GFW. HTML и API — напрямую с origin. Базовые подложки (CARTO, OSM, Esri)
  через CDN не проксируются: их условия запрещают кэширующий прокси, из РФ они и так быстрые.
- Redis: отдельный контейнер `forestwatch-redis` в compose проекта (общий `delivery-redis`
  не трогаем). Кэширует данные API, не плитки. Хранит свежее значение с TTL и «последнее
  удачное» без TTL — отдаётся, если источник упал или вернул пустоту.
- Порядок этапов: A → B → C → D, каждый деплоится отдельно.

## Этап A — фундамент

1. **Redis.** Сервис `redis` (`redis:7-alpine`) в `docker-compose.prod.yml`: сеть `internal`,
   том `forestwatch-redis-data`, `maxmemory 256mb`, `volatile-lru` (вытесняются только ключи с TTL — `last-good` не теряется), RDB-снапшоты
   (`save 300 10`), healthcheck `redis-cli ping`. Приложение: `REDIS_URL=redis://redis:6379`,
   `depends_on: redis (healthy)`.
2. **Кэш-хелпер** `backend/utils/cache.ts`: `cached(key, ttlSec, fetcher, { isValid })`.
   - Есть свежий ключ → вернуть.
   - Иначе fetcher; если результат валиден → записать `key` (TTL) и `key:last-good` (без TTL).
   - Fetcher упал или вернул невалидное → вернуть `key:last-good`, если есть; иначе ошибка.
   - Redis недоступен → работать без кэша (прямой вызов fetcher), не падать.
   - Клиент (ioredis) инжектится, в тестах — фейк на Map.
3. **Перевод кэшей на Redis:** FIRMS (TTL 1 ч), ООПТ (TTL 24 ч, невалиден пустой список),
   Рослесхоз (TTL 12 ч). Внутрипроцессные кэши удаляются.
4. **Сжатие:** `compression` middleware (gzip) для всех ответов.
5. **Заголовки кэша:** `/assets/*` → `public, max-age=31536000, immutable`;
   `index.html` → `no-cache`.
6. **CDN (opt-in):** build-arg `CDN_URL`. Vite `experimental.renderBuiltUrl` подставляет
   `${CDN_URL}/assets/...` для JS/CSS; пустой `CDN_URL` → относительные пути (как сейчас).
   CSP (helmet) получает хост CDN в `script-src`, `style-src`, `font-src`, `img-src`,
   `connect-src`. CORS уже включён глобально (`cors()`), CDN прокидывает заголовок.
   Включается только после проверки, что `cdn.forestwatch.ru` отдаёт наши ассеты по HTTPS.

Проверка: юнит-тесты хелпера (свежий хит, промах, last-good при ошибке/пустоте, Redis down);
после деплоя — `Content-Encoding: gzip`, `Cache-Control` на ассетах, ключи в Redis, переживание
рестарта контейнера приложения.

## Этап B — административные границы

- Источник: OSM через выгрузку Geofabrik `russia-latest.osm.pbf` (Overpass для тяжёлых
  запросов отвечает 504). 83 субъекта с `ISO3166-2 ~ ^RU-` (admin_level 4) и районы
  (admin_level 6) Иркутской обл., Бурятии, Забайкалья. Крым, Севастополь и регионы 2022 года
  не включаются (решение владельца).
- Сборка: `scripts/boundaries/build.sh` в Docker (osmium → mapshaper, упрощение, точность
  1e-4), файлы `frontend/public/data/boundaries/*.<версия>.geojson`, бюджет ≤300 КБ gzip.
  Скрипт проверяет: 83 субъекта, районы во всех трёх регионах, размер.
- Карта: модуль `frontend/src/map/boundariesLayer.ts`; слои «Границы субъектов РФ» (вкл.,
  подписи с z5) и «Муниципальные районы (Байкал)» (вкл., видны с z6, подписи с z8); hover,
  попап (название, тип, родитель, ссылка OSM, текст экранируется); растровый слой Esri удаляется.
  Атрибуция OSM (ODbL). Файлы грузятся через CDN.

## Этап C — данные

- Фоновое обновление в процессе приложения (node-cron + Redis-лок): FIRMS каждые 30 мин,
  ООПТ раз в сутки, Рослесхоз раз в сутки; пользователь никогда не ждёт источник.
- FIRMS: добавить NOAA-21. ООПТ: заголовок User-Agent, пустой ответ не принимается.
- Рослесхоз: актуальная версия набора через `meta.csv`, а не зашитые ссылки.
- Слои: потери леса → `latest` (v1.13), легенда по метаданным; GLAD Landsat → GLAD DIST-ALERT;
  «Лесной покров» → `umd_tree_cover_density_2000`; ФГИС ЛК WMS и OpenTopoMap — убрать.
- Прокси плиток GFW: `/tiles/gfw/...` на origin с `Cache-Control` (потери — 30 дней,
  DIST-ALERT — 1 день), клиент берёт их через `cdn.forestwatch.ru`.

## Этап D — скорость карты

- Термоточки: `L.circleMarker` на canvas (`preferCanvas`), по умолчанию bbox Байкальского
  региона, вся Россия — по переключателю.
- Code-splitting: `React.lazy` для страниц с recharts (Analytics) и карты.
- Бюджет: JS первой загрузки ≤ 250 КБ gzip.
