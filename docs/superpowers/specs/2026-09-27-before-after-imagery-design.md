# Снимки «до/после» для инцидентов (Sentinel-2)

Дата: 2026-09-27. Связано: future.md §7 «Детальная проверка», §14 «Третий релиз» п. 2.
Следующий шаг (NDVI и временные ряды, п. 3) переиспользует модуль чтения COG из этой задачи.

## Источник (проверено с VPS 2026-09-27)

- STAC: Element 84 Earth Search v1, `https://earth-search.aws.element84.com/v1`, коллекция
  `sentinel-2-c1-l2a` (Sentinel-2 L2A Collection 1, COG на AWS Open Data, без ключа).
  Поиск по bbox Иркутской области — 1,1 с; range-запрос к COG — 0,9 с.
- Ассеты: `visual` (TCI, 8 бит RGB, 10 м), `red` (B04, 10 м), `nir08` (B8A, 20 м),
  `swir22` (B12, 20 м), `scl` (классификация сцены, 20 м). Масштаб отражения —
  из `raster:bands` ассета (в C1: `scale 0.0001, offset -0.1`), не хардкодить.
- Лицензия: Copernicus Sentinel data — свободная и открытая; подпись
  «Contains modified Copernicus Sentinel data <год>». Каталог: Earth Search (Element 84), AWS Open Data.

## Решение: рендер в нашем Node, без TiTiler

- `geotiff` (geotiff.js, MIT) читает окно COG через HTTP range с выбором обзора (overview) под
  целевое разрешение; `proj4` переводит bbox WGS84 → UTM сцены (EPSG из `proj:code`/`proj:epsg`
  элемента); `sharp` (уже есть) кодирует PNG. Картинка остаётся в UTM (север вверх, поворот
  относительно WGS84 на участке ≤ 25 км пренебрежим — отметить в коде).
- Заглушки Replit удалить: `backend/routes/titiler.ts`, `backend/routes/stac.ts`,
  `backend/services/stacService.ts`, `backend/config/titiler.ts`, `frontend/src/api/titiler.ts`,
  `frontend/src/api/stac.ts` и их экспорт/подключение (смотрят на localhost, не работают в проде).
  Перед удалением убедиться, что их никто не использует.
- Проверить, что `geotiff` работает под ts-node (CommonJS) и в jest; если пакет только ESM —
  подобрать версию/способ импорта, который работает в обоих, и записать это в CLAUDE.md.

## Выбор снимков для инцидента

- Участок (AOI) = bbox инцидента, расширенный до стороны ≥ 3 км; если сторона > 20 км — квадрат
  20 км вокруг центра. Выходная картинка ≤ 512 px по длинной стороне.
- «До»: сцены с датой в [first_seen − 60 сут, first_seen − 1 сут]; перебирать от новых к старым.
- «После»: сцены после last_seen, от ранних к поздним; если их нет (инцидент активен или прошло
  мало времени) — самая новая сцена после first_seen с флагом `duringActivity: true`
  (подпись «снимок во время активности»).
- Поиск STAC: `eo:cloud_cover < 80`, пересечение с AOI, до 6 кандидатов на сторону.
- Для каждого кандидата читать `scl` по AOI: «чисто» = доля пикселей классов, кроме
  0 (нет данных), 1 (насыщение), 3 (тени облаков), 8, 9 (облака), 10 (перистые), 11 (снег).
  Класс 2 (тёмные участки) считать чистым — гари часто попадают в него. Брать первого кандидата
  с чистой долей ≥ 80 % и «нет данных» ≤ 5 % (AOI на краю полосы съёмки — брать другой тайл/дату).
- Если подходящих нет — `{ status: 'none', reason }`, причины: «нет безоблачных снимков за 60 дней
  до обнаружения», «снимков после обнаружения ещё нет», «участок под снегом». Никаких заглушек.
- Только для инцидентов с bbox/центром (сейчас это FIRMS-инциденты).

## Рендеры

- `truecolor` — ассет `visual` как есть.
- `swir` — B12 / B8A / B04 (20 м), отражение 0–0,4 → 0–255 с гаммой; гари тёмно-красные,
  активный огонь ярко-оранжевый. Для пожаров это основной вид.
- Поверх — тонкий жёлтый контур bbox инцидента (SVG-композит в `sharp`).

## HTTP

- `GET /api/monitoring/forest-changes/:id/imagery` →
  `{ incidentId, aoi, before, after, source: { name, url, license, attribution }, generatedAt }`,
  сторона: `{ status: 'ok', sceneId, datetime, platform, clearPct, duringActivity?, urls: { truecolor, swir } }`
  или `{ status: 'none', reason }`. Кэш `cached()` 24 ч, ключ
  `imagery:incident:v1:<id>:<last_seen>`; ошибка STAC/сети не сохраняется как хорошее значение.
- `GET /imagery/s2/v1/<sceneId>/<render>/<minLon>,<minLat>,<maxLon>,<maxLat>.png` — PNG,
  `Cache-Control: public, max-age=31536000, immutable` (содержимое определено сценой, bbox и
  версией рендера `v1`; новая логика рендера → `v2`). Проверки: `sceneId` по шаблону
  (`^S2[ABC]_T\d{2}[A-Z]{3}_\d{8}T\d{6}_L2A$`), `render` из белого списка, bbox с конечными числами,
  сторона ≤ 25 км, bbox пересекает footprint сцены — иначе 400. Элемент STAC по id кэшировать
  в Redis 30 сут; готовый PNG — 1 сут (долгое хранение — браузер и Beget CDN).
- Не более 2 рендеров одновременно (очередь), таймаут 25 с → 504, ошибка источника → 502.
- SPA-fallback в `backend/server.ts` (`/^\/(?!api\/|tiles\/).*/`) должен пропускать `/imagery/`.
- Во фронтенде URL картинок строить с префиксом `__CDN_URL__`, как плитки GFW. Новых внешних
  хостов в браузере нет — CSP не меняется (к AWS ходит сервер).

## Интерфейс

- В `IncidentModal` блок «Снимки до/после»: две картинки рядом (на телефоне — друг под другом),
  переключатель «Естественные цвета / SWIR (гари)», подписи: дата снимка, спутник
  (Sentinel-2A/B/C), доля чистых пикселей над участком, «во время активности» при
  `duringActivity`. Скелетон при загрузке; «нет данных» с причиной; «снимок не загрузился»
  при ошибке картинки. Под блоком — атрибуция и пояснение «снимки готовятся по запросу,
  первый показ — до 20 секунд».
- Все подписи — текстовые узлы React, без `innerHTML`.

## Тесты (jest)

Чистые функции: расширение AOI, окна поиска до/после, порядок кандидатов, доля чистых пикселей
SCL (включая класс 2 и снег), bbox → окно пикселей UTM, растяжка SWIR и масштаб `raster:bands`,
валидация маршрута (sceneId, render, bbox), ключи кэша, семафор. Чтение COG — через
инъецируемый интерфейс; один интеграционный тест на маленьком GeoTIFF, созданном в памяти
(`geotiff` `writeArrayBuffer` → `fromArrayBuffer`). Сети в тестах нет.

## Проверка после деплоя (делает основная сессия)

для 2–3 инцидентов Иркутской области, открыть PNG обоих рендеров, модалка на 1280 и 375 px.
