## Архитектура

### A. Сборка архива FIRMS (агент F) — без миграций, как границы

- `scripts/regional/build-firms-archive.sh` + чистый модуль агрегации (TypeScript/`.mjs`),
  запускается владельцем/сессией на VPS (из облака NASA может быть недоступна).
- Скачивает годовые CSV S-NPP 2019–2024, относит точки к 83 субъектам по
  `ru-regions.<версия>.geojson`, точки вне субъектов отбрасывает (Крым и т. п. — решение владельца).
- Результат — версионированные файлы в `frontend/public/data/regional/`:
  - `firms-archive.<последний год>.json`:
    `{ version, generatedAt, source: {name, urls, license}, years: [..], regions: { "<ISO>": { name, areaKm2, years: { "<год>": { vegetation, static, offshore, frpVegetation } } } } }`
    (`areaKm2` — площадь полигона субъекта из файла границ, `@turf/area`);
  - `firms-static-cells.<последний год>.json`: ячейки сетки 0,004° (как в `staticSources.ts`), где
    за 2022–2024 были точки `type = 2` — `{ version, gridDeg, cells: [[latIdx, lngIdx], …] }`.
- Маска факелов (`backend/services/firmsHistory/staticSources.ts`) дополнительно считает статичными
  ячейки из этого файла — факелы маскируются сразу, без ожидания двух недель истории.
- Бюджет: каждый файл ≤ 300 КБ gzip; скрипт проверяет число субъектов (83) и размер.

### B. Сервис и API регионов (агент G)

- `backend/services/regions/`:
  - реестр субъектов из файла границ (ISO, название, площадь);
  - **таблица соответствия названий Рослесхоза → ISO** (все 83, с тестом на полноту; строки
    «Всего…», федеральные округа, Крым/Севастополь/регионы 2022 г. явно исключаются);
  - сборка показателей из: Рослесхоз (`rosleskhozService`), архив FIRMS (файл из A), история NRT
    (`gis.fire_hotspots`), ООПТ (`overpassService`), GFW-оценка (`globalForestWatch`).
- `GET /api/regions` — таблица по 83 субъектам; `GET /api/regions/:iso` — детали с рядами по годам.
  Каждый показатель: `{ value, unit, period, source, kind: 'official'|'satellite'|'estimate', definition }`;
  нет данных → `value: null` + причина, никаких нулей вместо отсутствия.
- Нормализованные показатели:
  - термоточки растительности на 10 тыс. км² (год, по архиву);
  - отклонение года Y от среднего за 5 предыдущих лет, % (только полные годы архива);
  - потери на 100 тыс. га лесного фонда — только с пометкой `estimate`, пока нет `GFW_API_KEY`.
- Кэш: `cached()` 12 ч, фоновая задача не нужна (всё собирается из уже кэшированных источников).

### C. Интерфейс (агент G)

- Страница «Аналитика»: новый раздел «Регионы» — сортируемая таблица 83 субъектов (байкальские
  сверху), бейджи «официально / спутник / оценка», у каждой цифры период; клик — карточка субъекта:
  ряд термоточек 2019–2024 (растительность и статичные отдельно), официальные показатели,
  определения и источники, явное «нет региональных данных» там, где их нет.
- Мобильная ширина 375 px: таблица прокручивается горизонтально внутри блока, страница — нет.

## Разделение работы

- F: `scripts/regional/**`, `frontend/public/data/regional/**` (формат/пример), `backend/services/firmsHistory/staticSources.ts` и его тесты.
- G: `backend/services/regions/**`, `backend/routes/regions.ts`, `frontend/src/pages/AnalyticsPage.tsx` и новые компоненты/модули, тесты. G читает файлы из A по формату выше; до сборки реальных данных — фикстура в тестах.

## Вне рамок

Хороплет на карте, экспорт, реальные региональные потери GFW (нужен бесплатный ключ `GFW_API_KEY`).
