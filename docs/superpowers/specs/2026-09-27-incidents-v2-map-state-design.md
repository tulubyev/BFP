# Инциденты v2 и состояние карты

Дата: 2026-09-27. Связано: future.md §7 «Лента», «Карточка», «Детальная проверка» (пересечение
с ООПТ), §8 «Состояние карты в URL», критерии §15 («карта и инциденты используют одну модель»,
«событие можно открыть на карте и скачать»). Две независимые части — два агента.

## Часть K — лента и карточка инцидента

Файлы: `backend/services/forestChangesQuery.ts`, `incidentsService.ts`, `frontend/src/pages/IncidentsPage.tsx`,
`frontend/src/components/IncidentModal.tsx`, `IncidentCard.tsx`, новые модули. Не трогать
`IncidentImagery.tsx`, `NdviSeries.tsx`, `IncidentIndices.tsx`, карту (`MonitoringMap.tsx`, `frontend/src/map/`).

### Лента

- Фильтры: период (`start_date`/`end_date` уже есть в API — вывести в UI: «7 дней / 30 дней /
  90 дней / свой период»), статус FIRMS (`status=active|inactive`, новый параметр, белый список,
  `metadata->>'status'`, плейсхолдер), источник (`source=firms|…` по фактическим значениям в БД).
- Сортировка по уверенности (`confidence_desc`/`confidence_asc` в `FOREST_CHANGES_SORT_COLUMNS`,
  `NULLS LAST`).
- Все фильтры — в URL (как сейчас тип/регион/сортировка), выгрузка (`/api/export/incidents.*`)
  получает те же параметры — проверить, что `buildForestChangesQuery` общий и тест это ловит.
- Кэш ленты (`incidentsCache`) — ключ включает новые параметры.

### Карточка

- Мини-карта (Leaflet, как на главной, Esri Dark Gray): bbox инцидента и **его термоточки**
  (связанные наблюдения FIRMS: `gis.fire_hotspots` в пределах bbox + 375 м и окна
  first_seen…last_seen, спутник/время/FRP в подсказке) — новый
  `GET /api/monitoring/forest-changes/:id/hotspots` (только FIRMS-инциденты, предел 500 точек,
  кэш `cached()` 10 мин, ключ по id и last_seen). Кнопка «Открыть на большой карте» — ссылка с
  состоянием карты (часть L; до её слияния — текущий `/?lat&lng&incident`).
- Пересечение с ООПТ: по кэшу ООПТ (`getOOPT()`, полигоны) — «внутри ООПТ „…“» или «в N км от
  ООПТ „…“» (ближайшая граница, до 50 км, иначе «ООПТ в радиусе 50 км нет»), с датой данных ООПТ
  и пометкой «по границам OSM, приблизительно». Считать на сервере (`@turf/*` уже есть), отдавать
  в ответе `/hotspots` или отдельным полем — на выбор, кэш как выше.
- Нейтральное название: «Термоточки NASA FIRMS, Иркутская область, 25.09.2026» вместо «Пожар»
  для FIRMS-кластеров (тип «пожар» — предположение; подпись «вероятная причина: пожар
  растительности / постоянный источник тепла» по статусу).
- Раздел «Исходные данные»: сворачиваемый JSON инцидента (текстовый узел, `<pre>`).

## Часть L — карта: слой инцидентов и состояние в URL

Файлы: `frontend/src/components/MonitoringMap.tsx`, `frontend/src/pages/HomePage.tsx`,
`frontend/src/map/**`, `backend/routes/monitoring.ts` (только `/forest-changes/geojson`).
Не трогать страницу и карточку инцидентов (часть K).

- Слой «Инциденты» (включён по умолчанию): FIRMS-инциденты за последние 30 дней — контур bbox,
  а на мелком масштабе точка центра; цвет по статусу (активен / затих), постоянные источники
  тепла скрыты (как в ленте). Попап — текстовые узлы (`popup.ts`): тип, регион, даты, число
  точек, ссылка «Открыть карточку» (`/incidents?id=…`). Данные — `/api/monitoring/forest-changes/geojson`
  (сейчас LIMIT 500): добавить фильтры `start_date`, `static_sources` (те же парсеры, что у ленты),
  bbox видимой области не нужен при таком объёме.
- Состояние карты в URL (`useSearchParams`, `replace`, без засорения истории):
  `lat`, `lng`, `z` (центр/масштаб, 4–5 знаков), `layers` (список включённых оверлеев по
  стабильным id), `base` (подложка), `incident` (выбранный). Совместимость: старые ссылки
  `/?lat&lng&incident` работают как раньше. Невалидные значения игнорируются (чистые парсеры
  с тестами). Обновление URL — с задержкой (debounce) после `moveend`.
- Кнопка «Скопировать ссылку на карту» в панели.
- Производительность: не перерисовывать слои при каждом изменении URL; отмена устаревших
  запросов (`AbortController`) при смене фильтров слоя.

## Тесты (jest)

K: новые параметры запроса (белые списки, плейсхолдеры — тест-страж SQL должен пройти), ключи
кэша, выбор термоточек инцидента, расстояние/пересечение с ООПТ, нейтральное название.
L: парсинг/сериализация состояния карты (круговой тест), совместимость старых ссылок, стиль
слоя по статусу, фильтры geojson-эндпоинта.
